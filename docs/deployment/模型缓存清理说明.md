# 模型缓存清理说明

## 🔍 问题分析

从镜像分析结果看：
- **镜像总大小：9.89GB**
- **install.sh 层：8.09GB** ⚠️ 这是主要问题！

### 根本原因

`install.sh` 执行过程中，`sentence-transformers` 和 `chromadb` 等包在安装时**自动下载了大型模型文件**到缓存目录：

1. **Hugging Face 模型缓存** (`~/.cache/huggingface/`)
   - `sentence-transformers` 默认模型：~400-500MB
   - 如果使用更大的模型：~1-2GB

2. **PyTorch 缓存** (`~/.cache/torch/`)
   - PyTorch 模型和权重：~500MB-1GB

3. **Transformers 缓存** (`~/.cache/transformers/`)
   - 预训练模型：~500MB-2GB

4. **Chromadb 模型**
   - 可能包含嵌入模型：~100-500MB

**总计可能达到 2-5GB！**

## ✅ 已实施的优化

### 1. 防止安装时自动下载模型

```bash
# 设置环境变量，将模型缓存指向临时目录
export SENTENCE_TRANSFORMERS_HOME=/tmp
export TRANSFORMERS_CACHE=/tmp
export HF_HOME=/tmp
export TORCH_HOME=/tmp

# 安装依赖
pip install --no-cache-dir -r requirements/base.txt
```

### 2. 清理所有模型缓存

```bash
# 清理 Hugging Face 缓存
rm -rf ~/.cache/huggingface
rm -rf /root/.cache/huggingface

# 清理 PyTorch 缓存
rm -rf ~/.cache/torch
rm -rf /root/.cache/torch

# 清理 Transformers 缓存
rm -rf ~/.cache/transformers
rm -rf /root/.cache/transformers

# 清理所有缓存
rm -rf ~/.cache/*
rm -rf /root/.cache/*

# 清理临时目录中的模型文件
rm -rf /tmp/huggingface
rm -rf /tmp/transformers
rm -rf /tmp/torch
```

### 3. 在 Dockerfile 中最终清理

```dockerfile
# 最终清理：删除所有缓存和大型文件
RUN rm -rf /tmp/* /var/tmp/* && \
    rm -rf /root/.cache && \
    rm -rf /root/.cache/huggingface && \
    rm -rf /root/.cache/torch && \
    rm -rf /root/.cache/transformers && \
    # 查找并删除可能的模型文件（>50MB）
    find /opt/cozychat -type f -size +50M -not -path "*/\.venv/*" -delete 2>/dev/null || true
```

## 📊 预期效果

| 优化项 | 节省空间 | 说明 |
|--------|---------|------|
| Hugging Face 缓存 | ~500MB-2GB | 防止自动下载模型 |
| PyTorch 缓存 | ~500MB-1GB | 清理 PyTorch 权重 |
| Transformers 缓存 | ~500MB-2GB | 清理预训练模型 |
| 其他缓存 | ~200-500MB | 各种临时文件 |
| **总计** | **~1.7-5.5GB** | **预期镜像大小：~4-5GB** |

## 🚀 模型按需加载策略

### 当前实现

模型在**运行时按需下载**，而不是在构建时下载：

```python
# backend/app/engines/memory/qdrant_engine.py
def _get_embedding_model(self, model_name: str) -> SentenceTransformer:
    """获取或创建embedding模型（带缓存）"""
    # 首次使用时才下载模型
    model = SentenceTransformer(model_name, device='cpu')
    return model
```

### 优势

1. **镜像更小**：构建时不包含模型文件
2. **灵活性**：可以动态切换模型
3. **按需加载**：只下载实际使用的模型

### 注意事项

1. **首次运行较慢**：需要下载模型（~1-2分钟）
2. **需要网络**：首次运行时需要访问 Hugging Face
3. **模型缓存位置**：运行时模型会缓存在容器中（可通过 volume 持久化）

## 🔧 进一步优化建议

### 方案1: 使用更小的模型（推荐）

在配置中使用较小的模型：

```yaml
# backend/config/memory.yaml
embedding:
  model: "all-MiniLM-L6-v2"  # 小模型，~80MB
  # 而不是 "BGE-base-zh-v1.5"  # 大模型，~400MB
```

### 方案2: 预下载模型到 Volume

如果希望首次运行更快，可以在启动脚本中预下载：

```bash
# 在容器启动时预下载模型
python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('all-MiniLM-L6-v2')"
```

模型会缓存在 volume 中，不会增加镜像大小。

### 方案3: 使用外部模型服务

将模型部署到单独的服务，通过 API 调用：

```python
# 使用外部 embedding 服务
response = requests.post("http://embedding-service:8080/encode", json={"text": text})
embedding = response.json()["embedding"]
```

## ⚠️ 重要提示

1. **模型在运行时下载**：首次运行需要网络连接
2. **模型缓存位置**：运行时模型缓存在容器中，重启后需要重新下载（除非使用 volume）
3. **生产环境建议**：使用 volume 持久化模型缓存，避免每次重启都下载
