## 问题修复

### ✅ 已修复：API限流装饰器错误

**原错误信息**:
```
TypeError: login_user() missing 1 required positional argument: 'request'
```

**错误原因**:
1. `rate_limit` 装饰器修改了函数签名，将 `request: UserLoginRequest` 重命名为 `body`
2. 包装函数试图将 `body` 映射回 `request`
3. 但包装函数被调用了两次（slowapi也包装了函数）
4. 第二次调用时参数已经丢失

**修复方案**:
采用简化装饰器 + 添加Request参数的方案：
1. 完全重写 `rate_limit.py`，移除复杂的参数映射逻辑
2. 在所有需要限流的端点函数中添加 `Request` 类型参数（命名为 `http_request`）
3. 保持原有的 Pydantic 模型参数（命名为 `request`）

**修改的文件**:
- ✅ `backend/app/middleware/rate_limit.py` - 完全重写（从286行简化到242行）
- ✅ `backend/app/api/v1/users.py` - `login_user` 和 `register_user`
- ✅ `backend/app/api/v1/chat.py` - `create_chat_completion`
- ✅ `backend/app/api/v1/auth.py` - `refresh_token`
- ✅ `backend/app/api/v1/memory.py` - `create_memory` 和 `search_memories`
- ✅ `backend/app/api/v1/config.py` - `get_realtime_token`

**修复状态**: ✅ 已完成
