# N+1查询优化说明

## 📋 概述

本文档记录了CozyChat项目中N+1查询问题的识别和优化过程。

## 🔍 什么是N+1查询问题？

N+1查询是一个常见的ORM性能问题：
- **1次查询**：查询主表数据（如Session列表）
- **N次查询**：为每条主表记录查询关联表数据（如每个Session的Messages）

**示例**：
```python
# ❌ N+1查询（性能差）
sessions = db.query(Session).limit(10).all()  # 1次查询
for session in sessions:
    messages = db.query(Message).filter(
        Message.session_id == session.id
    ).all()  # N次查询（10次）
# 总计：11次数据库查询
```

## ✅ 已优化的查询

### 1. 会话详情查询 (`GET /v1/sessions/{session_id}`)

**位置**：`backend/app/api/v1/sessions.py:351-368`

**优化前**：
```python
# 查询会话
session = db.query(SessionModel).filter(
    SessionModel.id == session_uuid
).first()

# 单独查询消息（N+1问题）
messages = db.query(MessageModel).filter(
    MessageModel.session_id == session_uuid
).all()
```
**查询次数**：2次（1次session + 1次messages）

**优化后**：
```python
# 使用joinedload一次性加载
session = db.query(SessionModel).options(
    joinedload(SessionModel.messages)
).filter(
    SessionModel.id == session_uuid
).first()

# 使用关系属性（已加载，无额外查询）
messages = sorted(session.messages, key=lambda m: m.created_at)
```
**查询次数**：1次（使用LEFT OUTER JOIN）

**性能提升**：
- 查询次数减少：2次 → 1次（50%）
- 预期响应时间：~150ms → ~40ms（73%）

## 🛠️ 使用的优化技术

### 1. `joinedload()` - SQL JOIN

适用场景：
- **一对一**关系
- **一对多**关系（关联数据较少）
- 需要立即访问关联数据

优点：
- 只需1次查询
- 使用 SQL JOIN
- 适合小到中等数量的关联数据

缺点：
- 关联数据量大时，返回大量重复行
- 可能导致笛卡尔积

**使用示例**：
```python
from sqlalchemy.orm import joinedload

# 单个关系
session = db.query(Session).options(
    joinedload(Session.messages)
).first()

# 多个关系
user = db.query(User).options(
    joinedload(User.sessions),
    joinedload(User.preferences)
).first()

# 嵌套关系
session = db.query(Session).options(
    joinedload(Session.messages).joinedload(Message.user)
).first()
```

### 2. `selectinload()` - IN子查询

适用场景：
- **一对多**关系（关联数据较多）
- **多对多**关系
- 关联数据量大

优点：
- 避免笛卡尔积
- 适合大量关联数据
- 使用 IN (id1, id2, ...) 查询

缺点：
- 需要2次查询（主查询 + IN子查询）

**使用示例**：
```python
from sqlalchemy.orm import selectinload

# 一对多（数据量大）
users = db.query(User).options(
    selectinload(User.sessions)
).all()

# 多对多
posts = db.query(Post).options(
    selectinload(Post.tags)
).all()
```

### 3. `subqueryload()` - 子查询

适用场景：
- 复杂关联
- 需要独立的子查询

**使用示例**：
```python
from sqlalchemy.orm import subqueryload

users = db.query(User).options(
    subqueryload(User.sessions)
).all()
```

**方法3**：查看慢查询日志
```sql
-- PostgreSQL
SELECT query, calls, total_time, mean_time
FROM pg_stat_statements
ORDER BY mean_time DESC
LIMIT 10;
```

### 2. 选择合适的加载策略

| 关系类型 | 数据量 | 推荐策略 |
|---------|--------|---------|
| 一对一 | 任意 | `joinedload` |
| 一对多 | <100条 | `joinedload` |
| 一对多 | >100条 | `selectinload` |
| 多对多 | 任意 | `selectinload` |

### 3. 避免过度预加载

```python
# ❌ 避免：加载不需要的关系
session = db.query(Session).options(
    joinedload(Session.messages),
    joinedload(Session.user),
    joinedload(Session.metadata)  # 不需要
).first()

# ✅ 推荐：只加载需要的关系
session = db.query(Session).options(
    joinedload(Session.messages)
).first()
```

### 4. 结合索引优化

```python
# 确保外键有索引
class Message(Base):
    session_id = Column(UUID, ForeignKey("sessions.id"), index=True)
    user_id = Column(UUID, ForeignKey("users.id"), index=True)
```

### 2. 分析查询执行计划

```sql
-- PostgreSQL

SELECT sessions.*, messages.*
FROM sessions
LEFT OUTER JOIN messages ON sessions.id = messages.session_id
WHERE sessions.id = 'xxx';
```

### 3. 监控查询时间

```python
import time
from functools import wraps

def measure_query_time(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        elapsed = (time.time() - start) * 1000
        print(f"⏱️  {func.__name__}: {elapsed:.2f}ms")
        return result
    return wrapper
```
