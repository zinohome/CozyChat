## 1. 文档元数据规范

### 1.1 元数据格式

每个文档开头必须包含YAML front matter：

```markdown
---
title: 文档标题
version: 1.0.0
created: 2024-12-22
last_updated: 2024-12-22
status: active
author: 作者名
reviewers: [审阅者1, 审阅者2]
related_code:
  - backend/app/xxx.py
  - frontend/src/xxx.tsx
tags: [标签1, 标签2, 标签3]
---

# 文档标题

> **状态**: ✅ 活跃 | **最后更新**: 2024-12-22 | **版本**: 1.0.0

## 变更历史

- **2024-12-22 (v1.0.0)**: 初始版本

---

（文档正文）
```

### 1.2 必需字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `title` | string | 文档标题（必需） | "后端架构设计" |
| `version` | string | 文档版本（必需） | "1.0.0" |
| `created` | date | 创建日期（建议） | "2024-11-15" |
| `last_updated` | date | 最后更新日期（必需） | "2024-12-22" |
| `status` | string | 文档状态（必需） | "active" |

### 1.3 可选字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `author` | string | 作者 | "张军" |
| `reviewers` | array | 审阅者列表 | ["AI助手"] |
| `related_code` | array | 关联代码路径 | ["backend/app/core/"] |
| `tags` | array | 标签 | ["架构", "后端"] |

### 1.4 文档状态

| 状态 | 标记 | 含义 | 何时使用 |
|------|------|------|----------|
| `active` | ✅ | 活跃 | 文档与代码完全同步，可放心使用 |
| `outdated` | ⚠️ | 过时 | 部分内容过时，需要更新 |
| `deprecated` | ❌ | 废弃 | 已被新文档替代，不应再使用 |
| `draft` | 🚧 | 草稿 | 文档正在编写中，内容不完整 |
| `archived` | 📦 | 归档 | 历史文档，仅供参考 |

## 3. 更新现有文档

### 3.1 小修改（版本号不变）

只需更新 `last_updated` 字段：

```yaml
last_updated: 2024-12-22  # 更新为今天
```

在变更历史中记录：

```markdown
## 变更历史

- **2024-12-22**: 修正错别字，更新示例代码
- **2024-12-20 (v1.0.0)**: 初始版本
```

### 3.2 大修改（更新版本号）

更新 `version` 和 `last_updated`：

```yaml
version: 1.1.0  # 次版本号+1
last_updated: 2024-12-22
```

在变更历史中记录：

```markdown
## 变更历史

- **2024-12-22 (v1.1.0)**: 添加新章节，重构架构图
- **2024-12-20 (v1.0.0)**: 初始版本
```

### 3.3 版本号规范

采用语义化版本（Semantic Versioning）：

- **主版本号（Major）**: 重大变更，内容完全重写
  - 示例: `1.0.0` → `2.0.0`
  
- **次版本号（Minor）**: 增量更新，添加新章节
  - 示例: `1.0.0` → `1.1.0`
  
- **修订号（Patch）**: 小修改，修正错误
  - 示例: `1.0.0` → `1.0.1`

## 4. 废弃文档

### 4.1 标记为废弃

更新元数据：

```yaml
status: deprecated
```

在文档开头添加警告：

```markdown
# 旧版文档标题

> ⚠️ **已废弃**: 此文档已被 [新文档](../new-doc.md) 替代，请使用新版本。
>
> **废弃日期**: 2024-12-22  
> **移除时间**: 2025-01-22（1个月后）
```

### 4.2 移至归档

1个月后，将文档移至 `docs/archives/`：

```bash
mv docs/old-doc.md docs/archives/old-doc.md
```

更新状态：

```yaml
status: archived
```

## 5. 自动化工具

### 5.1 文档管理器

#### 扫描文档

```bash
python scripts/docs_manager.py scan
```

输出示例：
```
🔍 扫描文档目录...
✅ 找到 150 个文档
```

#### 生成索引

```bash
python scripts/docs_manager.py index
```

生成 `docs/INDEX.md`，包含：
- 所有文档列表
- 按分类组织
- 状态标记
- 最后更新时间

#### 检查过期文档

```bash
python scripts/docs_manager.py check
```

输出示例：
```
🔍 检查过期文档...

⚠️  发现 5 个过期文档（超过30天未更新）:

  - 前端架构设计
    路径: architecture/03-前端架构设计.md
    最后更新: 45天前
    关联代码: frontend/src/

  - ...
```

#### 生成详细报告

```bash
python scripts/docs_manager.py report
```

生成 `docs/DOCS_REPORT.json`，包含：
- 所有文档的元数据
- 统计信息
- 过期文档列表

### 5.2 元数据检查（Pre-commit）

#### 手动检查

```bash
python scripts/check_docs_metadata.py docs/my-doc.md
```

输出示例：
```
🔍 检查 1 个文档的元数据...

✅ docs/my-doc.md

✅ 所有文档元数据检查通过！
```

#### 自动检查（Git Hook）

配置 `.pre-commit-config.yaml`：

```yaml
repos:
  - repo: local
    hooks:
      - id: check-docs-metadata
        name: 检查文档元数据
        entry: python scripts/check_docs_metadata.py
        language: system
        files: \.md$
        pass_filenames: true
```

安装pre-commit hook：

```bash
pre-commit install
```

提交文档时自动检查：

```bash
git add docs/my-doc.md
git commit -m "docs: 更新文档"

# 自动运行元数据检查
检查文档元数据...................................................✅
```

## 6. 最佳实践

### 6.1 代码变更时同步更新文档

**场景**: 修改了后端架构

```markdown
[ ] 修改代码
[ ] 运行测试
[ ] 更新相关文档:
    [ ] 更新 docs/architecture/02-后端架构设计.md
    [ ] 更新 last_updated 字段
    [ ] 更新版本号（如需要）
    [ ] 在变更历史中记录
[ ] 提交（代码 + 文档）
```

### 6.2 定期审查文档

**建议频率**: 每月一次

```bash
# 1. 检查过期文档
python scripts/docs_manager.py check

# 2. 更新过期文档
#    - 验证内容是否准确
#    - 更新过时信息
#    - 更新 last_updated 字段

# 3. 重新生成索引
python scripts/docs_manager.py index

# 4. 提交更新
git add docs/
git commit -m "docs: 月度文档审查和更新"
```

### 6.3 文档生命周期

```
创建 (draft)
    ↓
完成 (active)
    ↓
代码变更 → 更新文档 (active)
    ↓
内容过时 (outdated)
    ↓
重写或废弃 (deprecated)
    ↓
归档 (archived)
```

### 6.4 PR中的文档检查清单

提交PR时，检查：

```markdown
[ ] 所有相关文档已更新
[ ] 文档元数据完整（title, version, last_updated, status）
[ ] 变更历史已记录
[ ] 状态标记正确
[ ] 关联代码路径正确
[ ] Pre-commit检查通过
```

## 7. 常见问题

### Q1: 如何查找某个功能的文档？

**方法1**: 使用文档索引

```
打开 docs/INDEX.md，按分类查找
```

**方法2**: 使用标签搜索

```bash
grep -r "tags:.*功能名" docs/
```

**方法3**: 使用代码关联

```bash
grep -r "related_code:.*文件路径" docs/
```

### Q2: 文档过期了，但我没时间更新？

**临时方案**:

1. 更新状态为 `outdated`：
   ```yaml
   status: outdated
   ```

2. 添加警告：
   ```markdown
   > ⚠️ **注意**: 部分内容可能过时，待更新。
   ```

3. 创建TODO issue：
   ```
   TODO: 更新文档 - [文档名]
   - 内容: 哪些部分需要更新
   - 原因: 为什么过时
   - 优先级: 高/中/低
   ```

### Q3: 如何处理临时文档？

**建议**:

1. 临时笔记放在 `docs/temp/`
2. 不需要完整元数据
3. 定期清理（每月）

### Q4: 文档太多，如何维护？

**策略**:

1. **优先级分类**:
   - 核心文档（架构、API）: 必须保持最新
   - 功能文档: 重要功能需更新
   - 参考文档: 可容忍一定滞后

2. **自动化提醒**:
   ```bash
   # 每周运行
   python scripts/docs_manager.py check | grep "⚠️"
   ```

3. **团队协作**:
   - 谁改代码谁更新文档
   - Code Review时检查文档

## 8. 工具集成

### 8.1 CI/CD集成

在CI中添加文档检查：

```yaml
# .github/workflows/docs-check.yml
name: 文档检查

on: [push, pull_request]

jobs:
  check-docs:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: 检查文档元数据
        run: |
          python scripts/check_docs_metadata.py $(git diff --name-only origin/main...HEAD | grep '\.md$')
      
      - name: 检查过期文档
        run: |
          python scripts/docs_manager.py check
```

### 8.2 VSCode集成

安装扩展：
- `yzhang.markdown-all-in-one`: Markdown编辑
- `bierner.markdown-yaml-preamble`: YAML front matter支持

### 8.3 自动更新last_updated

创建VSCode snippet：

```json
{
  "Update last_updated": {
    "scope": "markdown",
    "prefix": "update-date",
    "body": [
      "last_updated: ${CURRENT_YEAR}-${CURRENT_MONTH}-${CURRENT_DATE}"
    ]
  }
}
```
