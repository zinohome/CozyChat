## 📊 配置体系总览

### 核心理念

CozyChat 的配置体系采用**四层架构**，从底层到顶层依次为：

```
代码默认值 → 环境变量 → 功能配置 → Personality配置
```

每一层都有明确的职责，通过**覆盖**和**继承**机制组合成最终配置。

### 配置流程图（从底层到顶层）

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: 代码默认值（最底层）                               │
│     - 硬编码的默认值（最后的后备）                            │
│     - 当所有配置层都没有提供值时使用                           │
└─────────────────────────────────────────────────────────────┘
                        ↓ 覆盖
┌─────────────────────────────────────────────────────────────┐
│  Layer 2: 环境变量 (.env)（倒数第二层）                      │
│     - 敏感信息（API密钥、密码）                               │
│     - 环境相关（数据库URL、Redis URL）                        │
│     - 运行时配置（环境标识、调试开关）                         │
│     - 必须的设置值，覆盖代码默认值                             │
└─────────────────────────────────────────────────────────────┘
                        ↓ 覆盖
┌─────────────────────────────────────────────────────────────┐
│  Layer 3: 功能配置 (YAML)（倒数第三层）                      │
│     ├── 引擎配置 (models/*.yaml)                            │
│     │   - openai.yaml, ollama.yaml, lmstudio.yaml           │
│     │   - 定义引擎能力、支持的模型、默认参数                  │
│     ├── 功能配置 (memory.yaml, session.yaml, ...)           │
│     │   - 定义功能的默认值和选项                             │
│     └── 语音配置 (voice/*.yaml)                              │
│         - stt.yaml, tts.yaml, realtime.yaml                  │
│     - 保证功能的完整，覆盖环境变量                             │
└─────────────────────────────────────────────────────────────┘
                        ↓ 选择和简化（最高优先级）
┌─────────────────────────────────────────────────────────────┐
│  Layer 4: Personality配置 (personalities/*.yaml)（最上层） │
│     - 从多个引擎中选择一个（多选一）                          │
│     - 从功能配置中选择和定制参数                              │
│     - 只包含需要覆盖的配置项                                  │
│     - 未配置项自动继承功能配置的默认值                        │
│     - 应用直接调用，最终使用的配置                             │
└─────────────────────────────────────────────────────────────┘
```

### 配置优先级（从底层到顶层）

```
Personality配置 > 功能配置 > 环境变量 > 代码默认值
```

**说明**：
- **代码默认值**：最底层，提供基础默认值
- **环境变量**：倒数第二层，设置必须的配置值（敏感信息、环境相关）
- **功能配置**：倒数第三层，保证功能的完整性和默认值
- **Personality配置**：最上层，应用直接调用，最终使用的配置

## 🔍 问题分析

### 当前问题

1. **`.env` 文件内容过多**（100+行）
   - 包含应用配置、业务逻辑配置、功能开关、性能参数等
   - 难以维护和管理

2. **配置重复和混乱**
   - 记忆系统配置：`.env` 中的 `MEMORY_*` 与 `memory.yaml` 重复
   - 会话配置：`.env` 中的 `SESSION_TITLE_*` 与 `session.yaml` 重复
   - 向量数据库：`.env` 中的 `QDRANT_URL` 与 `memory.yaml` 重复
   - 智能上下文：`.env` 中有 `CONTEXT_*`，但没有对应的 YAML 文件

3. **配置加载逻辑不统一**
   - 部分配置从 `.env` 读取（通过 `Settings`）
   - 部分配置从 YAML 读取（通过 `ConfigLoader`）
   - 没有统一的环境变量覆盖机制

4. **配置职责不清晰**
   - 敏感信息（API密钥、密码）与业务配置混在一起
   - 环境相关配置与功能配置混在一起
   - Personality 配置与引擎配置的关系不明确

## 🏗️ 四层配置架构（从底层到顶层）

### Layer 1: 代码默认值（最底层）

**职责**：作为最后的后备，提供合理的默认值

**使用场景**：
- 当所有配置层都没有提供值时使用
- 作为配置验证失败时的后备
- 提供最基础的默认值

**特点**：
- 硬编码在代码中
- 优先级最低
- 作为所有配置的基础

### Layer 2: 环境变量 (.env)（倒数第二层）

**职责**：设置必须的配置值，覆盖代码默认值

**包含内容**：
- ✅ 敏感信息：API密钥、密码、Token（必须设置）
- ✅ 环境相关：数据库URL、Redis URL、服务地址（必须设置）
- ✅ 运行时配置：环境标识、调试开关（必须设置）
- ❌ 不包含：业务逻辑配置、功能开关、性能参数

**特点**：
- 必须的设置值，覆盖代码默认值
- 优先级高于代码默认值，低于功能配置
- 不同环境使用不同的值

**示例**：
```bash
# 敏感信息
OPENAI_API_KEY=sk-xxx
TENCENT_SECRET_ID=xxx
TENCENT_SECRET_KEY=xxx

# 环境相关
DATABASE_URL=postgresql://user:pass@host:port/db
REDIS_URL=redis://host:6379/0
QDRANT_URL=http://qdrant:6333

# 运行时配置
APP_ENV=production
APP_DEBUG=false
```

### Layer 3: 功能配置 (YAML)（倒数第三层）

**职责**：保证功能的完整，提供完整的配置选项和默认值

**包含内容**：
- **引擎配置** (`models/*.yaml`)：定义引擎的能力和默认值
- **功能配置** (`memory.yaml`, `session.yaml`, `context.yaml`, ...)：定义功能的默认值
- **语音配置** (`voice/*.yaml`)：定义语音引擎的配置

**特点**：
- 支持环境变量占位符（`${VAR_NAME}`）
- 提供完整的配置选项和默认值
- 保证功能的完整性
- 可以被 Personality 配置选择和覆盖
- 优先级高于环境变量，低于 Personality 配置

### Layer 4: Personality配置 (YAML)（最上层）

**职责**：应用直接调用，最终使用的配置

**核心作用**：
1. **多选一**：从多个同类引擎中选择一个（如从 openai/ollama/lmstudio 中选择 AI 引擎）
2. **选择模型**：从选定引擎支持的模型列表中选择
3. **定制参数**：覆盖引擎配置和功能配置的默认参数
4. **简化配置**：只配置需要覆盖的项，不需要重复所有配置
5. **继承默认值**：未配置的项自动使用功能配置的默认值

**特点**：
- 应用直接调用，最终使用的配置
- 优先级最高
- 对功能配置进行选择和简化
- 为特定人格定制参数

## 🔄 配置优先级和合并规则

### 配置优先级（从底层到顶层）

```
Personality配置 > 功能配置 > 环境变量 > 代码默认值
```

**说明**：
- **代码默认值**（Layer 1）：最底层，提供基础默认值
- **环境变量**（Layer 2）：倒数第二层，设置必须的配置值
- **功能配置**（Layer 3）：倒数第三层，保证功能的完整性
- **Personality配置**（Layer 4）：最上层，应用直接调用，最终使用的配置

### 合并规则

#### 1. 环境变量覆盖代码默认值

环境变量覆盖代码默认值：

```python
# 代码默认值
DEFAULT_SIMILARITY_THRESHOLD = 0.7

# .env
MEMORY_RETRIEVAL_SIMILARITY_THRESHOLD=0.5  # 覆盖代码默认值
```

#### 2. 功能配置覆盖环境变量

功能配置提供默认值，优先级高于环境变量：

```yaml
# memory.yaml（功能配置）
memory:
  retrieval:
    similarity_threshold: 0.7  # 默认值

# .env（如果设置了环境变量）
MEMORY_RETRIEVAL_SIMILARITY_THRESHOLD=0.5  # 会被功能配置的默认值覆盖
```

**说明**：
- 功能配置的默认值优先级高于环境变量
- 环境变量主要用于提供敏感信息（如API密钥），通过 `${VAR_NAME}` 占位符在功能配置中引用
- 功能配置的业务逻辑参数（如相似度阈值）会覆盖环境变量中的对应值

#### 3. Personality 配置覆盖功能配置（最高优先级）

Personality 配置可以覆盖功能配置的默认值，这是应用最终使用的配置：

```yaml
# memory.yaml（功能配置）
memory:
  retrieval:
    similarity_threshold: 0.7      # 默认值
    timeout_seconds: 0.5            # 默认值

# personalities/health_assistant.yaml（Personality 配置）
memory:
  retrieval:
    similarity_threshold: 0.3       # ✅ 覆盖为 0.3（应用最终使用）
    # timeout_seconds 未配置        # ✅ 继承功能配置的 0.5（应用最终使用）
```

#### 4. Personality 选择引擎（应用直接调用）

Personality 从多个引擎中选择一个，并可以定制参数，这是应用最终使用的配置：

```yaml
# models/openai.yaml（引擎配置）
engine:
  default:
    model: "gpt-3.5-turbo"      # 默认模型
    temperature: 0.7            # 默认温度
    max_tokens: 2048            # 默认最大token

# personalities/health_assistant.yaml（Personality 配置）
ai:
  provider: "openai"            # ✅ 选择 OpenAI 引擎（应用最终使用）
  model: "gpt-4.1"              # ✅ 选择 gpt-4.1 模型（应用最终使用）
  temperature: 0.7              # ✅ 使用引擎默认值（应用最终使用）
  max_tokens: 8192              # ✅ 覆盖为 8192（应用最终使用）
```

- ❌ `CONTEXT_*` → 移到 `context.yaml`（新建）
- ❌ `PERFORMANCE_*` → 移到 `performance.yaml`（新建）

### Layer 3: 功能配置 (YAML)（倒数第三层）

#### 2.1 引擎配置 (`models/*.yaml`)

**职责**：定义每个引擎的能力、支持的模型、默认参数

**文件结构**：
```
models/
├── openai.yaml      # OpenAI 引擎配置
├── ollama.yaml      # Ollama 引擎配置
└── lmstudio.yaml    # LM Studio 引擎配置
```

**配置示例** (`models/openai.yaml`)：
```yaml
engine:
  name: "openai"
  display_name: "OpenAI"
  description: "OpenAI GPT模型"
  provider: "openai"
  
  # 默认配置
  default:
    model: "gpt-4.1"
    temperature: 0.7
    max_tokens: 2048
    base_url: "${OPENAI_BASE_URL}"  # 从环境变量读取
    api_key: "${OPENAI_API_KEY}"    # 从环境变量读取（敏感信息）
  
  # 支持的模型列表
  models:
    - name: "gpt-4.1"
      display_name: "GPT-4"
      max_tokens: 8192
      supports_streaming: true
      supports_function_calling: true
    - name: "gpt-3.5-turbo"
      display_name: "GPT-3.5 Turbo"
      max_tokens: 4096
      supports_streaming: true
      supports_function_calling: true
  
  # API配置
  api:
    timeout: 60
    max_retries: 3
    retry_delay: 1.0
  
  # 功能支持
  features:
    streaming: true
    function_calling: true
    vision: false
    audio: true
```

#### 2.2 功能配置

**记忆系统配置** (`memory.yaml`)：
```yaml
memory:
  # 默认向量数据库引擎
  default_engine: "qdrant"  # chromadb / qdrant / cognee
  
  # 存储模式
  storage_mode: "hybrid"  # dual/unified/hybrid
  
  # 异步写入配置
  async_write: true
  batch_size: 10
  
  # 去重配置
  dedup:
    enabled: true
    mode: "async"
    content_threshold: 5
    storage_threshold: 0.8
    check_interval_seconds: 300
  
  # Qdrant配置
  qdrant:
    engine: "qdrant"
    url: "${QDRANT_URL}"  # 从环境变量读取
    api_key: "${QDRANT_API_KEY}"  # 从环境变量读取
    collection_prefix: "cozychat_"
    embedding:
      model: "all-MiniLM-L6-v2"
      dimension: 384
    performance:
      batch_size: 100
      max_retries: 3
  
  # 检索配置（默认值）
```

### Layer 4: Personality配置 (personalities/*.yaml)（最上层）

**职责**：对功能配置进行选择和简化，为特定人格定制参数

**配置示例** (`personalities/health_assistant.yaml`)：
```yaml
personality:
  id: "health_assistant"
  name: "健康助手小研"
  version: "1.0.0"
  description: "专业的健康咨询助手"
  welcome_message: "您好，我是健康助手小研~有什么健康问题可以随时问我哦！"
  
  # 人格特征（Personality 特有）
  traits:
    friendliness: 0.8
    formality: 0.6
    humor: 0.4
    empathy: 0.9
  
  # AI引擎配置（从多个引擎中选择一个，并定制参数）
  ai:
    provider: "openai"           # ✅ 多选一：从 openai/ollama/lmstudio 中选择
    model: "gpt-4.1"             # ✅ 选择该引擎支持的模型
    temperature: 0.7             # ✅ 定制参数（覆盖引擎配置的默认值）
    max_tokens: 8192             # ✅ 定制参数（覆盖引擎配置的默认值）
    system_prompt: |             # ✅ Personality 特有的提示词
      你是一个专业的健康咨询助手...
    token_budget:                # ✅ 定制 Token 预算
      max_history_tokens: 4000
      max_memory_tokens: 1000
      max_tool_tokens: 500
  
  # 记忆配置（从 memory.yaml 选择和定制）
  memory:
    enabled: true
    vector_db: "qdrant"          # ✅ 选择使用哪个向量数据库
    save_mode: "both"
    
    # 记忆策略（定制参数，覆盖 memory.yaml 的默认值）
    strategy:
      user_memory:
        enabled: true
        importance_threshold: 0.5  # 定制阈值
        max_memories: 100          # 定制最大记忆数
        ttl_days: 90               # 定制过期时间
    
    # 检索配置（定制参数，覆盖 memory.yaml 的默认值）
    retrieval:
      similarity_threshold: 0.3   # ✅ 覆盖为 0.3（功能配置默认是 0.7）
      # timeout_seconds 未配置    # ✅ 继承功能配置的默认值 0.5
      # max_results 未配置        # ✅ 继承功能配置的默认值 5
  
  # 工具配置（从 tools/*.yaml 选择）
  tools:
    enabled: true
```

## 🔗 配置关系图

### Personality 选择引擎的流程

```
Personality 配置
  ai:
    provider: "openai"  ←─── 选择引擎
         ↓
    加载 models/openai.yaml
         ↓
    使用引擎默认值
    - model: "gpt-3.5-turbo"
    - temperature: 0.7
    - max_tokens: 2048
         ↓
    Personality 配置覆盖
    - model: "gpt-4.1"        ←─── 覆盖
    - temperature: 0.7        ←─── 继承（未覆盖）
    - max_tokens: 8192        ←─── 覆盖
         ↓
    最终配置
    - provider: "openai"
    - model: "gpt-4.1"
    - temperature: 0.7
    - max_tokens: 8192
```
