## 2. 问题分析

### 2.1 SQLAlchemy ORM属性类型问题（109个arg-type）

**问题根源**：
- SQLAlchemy ORM属性在类型检查器看来是`Column[str]`类型
- 实际运行时是`str`类型
- 需要`str()`转换或`type: ignore[arg-type]`

**典型示例**：
```python
# 当前代码
if str(user.status) != "active":  # type: ignore[arg-type]
    pass

# 问题：类型检查器认为user.status是Column[str]，不能直接用于str()转换
```

**改进方案**：
1. 使用SQLAlchemy 2.0的`Mapped`类型注解
2. 使用类型保护函数
3. 改进模型定义

### 2.2 ORM属性赋值问题（23个assignment）

**问题根源**：
- ORM属性赋值时，类型检查器认为类型不匹配
- 需要`type: ignore[assignment]`

**典型示例**：
```python
# 当前代码
session.title = "新标题"  # type: ignore[assignment]
```

**改进方案**：
1. 使用`Mapped`类型注解
2. 使用`mapped_column`定义列

### 2.3 导入未类型化库（10个import-untyped）

**问题根源**：
- 第三方库没有类型存根文件
- 如`zhconv`等

**改进方案**：
1. 使用`py.typed`标记
2. 创建类型存根文件
3. 使用`TYPE_CHECKING`条件导入

### 2.4 其他问题

- **attr-defined**: 动态属性访问
- **misc**: 复杂的类型推断问题
- **comparison-overlap**: 比较操作类型重叠

## 3. 改进策略

### 3.1 优先级1：SQLAlchemy ORM类型改进（预计减少60-70个）

**目标**：使用SQLAlchemy 2.0的`Mapped`类型注解

**步骤**：
1. 更新模型定义，使用`Mapped[str]`等类型注解
2. 使用`mapped_column`定义列
3. 移除相关的`type: ignore[arg-type]`和`type: ignore[assignment]`

**预期效果**：
- 减少`arg-type`: 60-70个

3. 移除相关的`type: ignore[arg-type]`

**预期效果**：
- 减少`arg-type`: 10-15个

### 3.3 优先级3：可选类型处理（预计减少5-10个）

**步骤**：

3. 移除不必要的`type: ignore[arg-type]`

**预期效果**：
- 减少`arg-type`: 5-10个

### 3.4 优先级4：第三方库类型存根（预计减少5-8个）
